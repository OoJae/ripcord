System

Two models argue. A deterministic Guard decides.

Ripcord's core belief: model intelligence proposes, deterministic code disposes. Every tick runs the same loop, and nothing an LLM says can move money on its own.

The loop

  1. 01 · Sense

    Reads the position directly from the chain — health factor, balances, prices. The Aave oracle is cross-checked against an independent Chainlink feed; a divergent price blocks any defense, because acting on corrupted pricing is worse than waiting.

  2. 02 · Plan

    A Planner model proposes exactly one action with one amount and its expected outcome. It cannot name an address or a contract — those exist only in an allowlisted config the model never touches.

  3. 03 · Critique

    An independent Critic model reviews the plan against verified figures it is given separately. Anything but an explicit APPROVE ends the tick. No approval, no transaction — ever.

  4. 04 · Guard

    Fourteen deterministic rules re-derive every number the models claimed. The Guard is final authority: it can veto both models, and nothing can veto the Guard.

  5. 05 · Execute

    The defense lands through a KeeperHub workflow that re-reads the chain and refuses to write if the position no longer needs defending — retries, smart gas, and sponsorship included. The daemon holds no signing keys at all.

The fourteen rules

action-none
"do nothing" is a valid plan, and it never executes
critic-approval
strict APPROVE required — anything else blocks
allowlist
assets resolve only through config; a raw address anywhere in model output is fatal
amount-positive
finite and positive, or blocked
max-tx-usd
per-transaction cap, compared in integer cents
daily-cap
rolling 24-hour spend; failed attempts still count against it
min-hf-improvement
gated on the Guard's own arithmetic, never the model's claim
hf-claim-honesty
a model overstating its outcome is itself grounds to block
snapshot-provenance
the position defended must be the position actually read
oracle-sanity
Aave's price cross-checked against Chainlink; divergence blocks
wallet-reserve-floor
never spends the wallet's last dollar silently
wallet-solvency
the repay must fit the balance — checked deterministically
idempotency
one decision, one defense, ever
arm-flag
mainnet writes require an explicit human arm on top of everything

Every rule runs on every decision — no short-circuits — and every check is written to the audit trail. DRY_RUN is evaluated last, which is why a clean pass reads "all 15 safety checks passed".

Modes — whose hand is on the handle

advisory

Full pipeline, real alerts, never executes. A recommendation engine.

copilot

The defense is built and held for your explicit approval. Silence means no.

autopilot

Acts on its own, but announces a cancel window first. Silence means go.

The two failure postures are opposite on purpose: a mode built on consent must not act when you never answered, and a mode built on autonomy must not be disarmed by an unread notification. Panic overrides all three — an unreachable owner must not become a liquidation.

What Ripcord is not

It funds defenses from wallet USDC — the flash-loan, repay-from-collateral path the incumbents use is on the roadmap, stated plainly in the code rather than hidden. Private transaction routing is Ethereum-only on KeeperHub today, so Base defenses run public with the tradeoff documented. The limits are in the repo next to the things that work.
